# Memory Architecture Optimization Roadmap

## 当前架构瓶颈

```
┌─ 工作记忆 (turns) ──────────────────────────┐
│ [{role, content}, ...]  ← 最多 15 条，纯扁平   │
│ 超限 → LLM 压缩成自然语言摘要 → 丢弃原文       │
└──────────────────────────────────────────────┘
┌─ 长期记忆 (memory) ─────────────────────────┐
│ "The bot collected wood and crafted..."      │
│ 一段自然语言字符串，非结构化                   │
└──────────────────────────────────────────────┘
┌─ 示例/技能检索 (Examples + SkillLibrary) ────┐
│ 全量余弦相似度排序 → topN                     │
│ 无索引、无持久化、无混合检索                   │
└──────────────────────────────────────────────┘
```

核心问题：**所有信息被压缩成一维的自然语言文本，丢失了结构关系。**

## 推进路线

| 优先级 | 方向 | 理由 |
|--------|------|------|
| **P0** | [动作-状态转移图](./01-action-state-graph.md) | 直接解决「重复规划」问题，高频路径免 LLM |
| **P1** | [双层检索 + 持久化向量索引](./02-dual-retrieval.md) | 提升示例/技能检索质量，可复用现有 embedding 代码 |
| **P2** | [树形任务记忆](./03-task-tree.md) | 复杂任务的分解和复用，需配合图结构 |
| **P3** | [知识图谱](./04-knowledge-graph.md) | 世界知识的显式化，但维护成本高 |

P0 和 P1 可并行推进——图结构改的是 agent 的行为决策层，检索改的是 prompt 构建层，两者互不冲突。
