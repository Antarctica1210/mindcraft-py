可以提高的地方不少，但我觉得最有价值的是把 bot 从“LLM 每步猜动作”升级成“有任务感、环境感、进度感的队友”。

**最优先的方向**

1. **长任务续跑，而不是 max loop 后失败**  
   像“种 43 个种子”这种任务，不应该因为本轮 loop 用完就失败。可以改成：
   - 当前轮结束但目标未完成时，状态变成 `running/needs_more_steps`
   - 保留 task stack 和 progress
   - 下一轮继续同一个任务
   - 只有真实 blocker 才失败，比如没种子、没锄头、无法到达

2. **批量技能替代逐格 LLM 操作**  
   现在 LLM 可能是：找一块草地 -> 种一格 -> 再找。  
   更好的方式是封装技能：
   - `plantSeedsNearPlayer(count)`
   - `collectAnyWood(count)`
   - `mineOreWithRequiredTool(ore, count)`
   - `craftWithDependencies(item, count)`
   
   让 LLM 负责目标，代码负责稳定执行。这个会极大提升成功率。

3. **更泛化的依赖规划**  
   现在已经有 missing tool/material recovery，可以继续扩展成小型 dependency planner：
   - 缺镐 -> 看有没有木头/石头 -> 做木镐/石镐/铁镐
   - 缺燃料 -> 优先 coal/charcoal/planks
   - 缺木头 -> 接受任意 `*_log`，不是只找 oak
   - 缺工作台/熔炉 -> 自动制作/放置/使用

4. **空间感和工作区规划**  
   Bot 现在很多时候是局部找方块，容易低效。可以加入：
   - 记录最近可用资源点
   - 任务开始时选择 worksite
   - 种田时规划连续区域，而不是随机找草地
   - 交付任务必须回到玩家附近
   - path timeout 后换目标点，而不是一直卡死

5. **更好的任务进度表达**  
   游戏内只说短句，但要有“队友感”：
   - `种植中：16/43`
   - `缺少 stone_pickaxe，先制作`
   - `已完成，正在回到你身边`
   - `任务失败：缺少种子。我可以接受新命令了`

**中期可以做**

- **知识图谱/RAG 更贴近行动系统**：把知识转成行动约束，比如“iron_ore 需要 stone_pickaxe+”，“torch 可用 coal 或 charcoal”。
- **记忆质量门控继续收紧**：只记可复用教训，不记噪声任务总结。
- **失败分类更细**：区分缺材料、路径超时、目标不存在、工具等级不足、背包不足、玩家太远。
- **自动 benchmark**：从日志里抽取典型任务，统计成功率、平均命令数、失败原因。

**我最建议的下一步**

先做两个高收益改动：

1. `max loop 用完时不要直接失败，而是继续当前 task`
2. 给种植/收集/制作依赖做批量技能

这两个会直接改善你现在日志里最常见的问题：大任务没完成、重复找方块、一步步操作太慢。
